summit

UI mockups

All three use your real tracks and audio (when launched with uv run mockups/app.py). The 12 clusters, tags, BPMs and keys are fake assignments. Space plays/pauses, ⇧← / ⇧→ go to previous/next, ⌥+hover auditions. ctrl+alt+shift+D toggles help tips. The CLAP / EffNet / Combined toggle shows deliberately different layouts: CLAP is blurrier, EffNet more separated.

A

Map + side panel

The map is the main view. A side panel shows whatever you clicked, lassoed or searched.

  • Track detail, tags, Discogs styles, neighbours
  • Selection tab: tag all, save playlist, teach a vibe
  • Editable cluster names
B

Tagging workbench

A map plus a rekordbox-style track table, built for tagging the untagged library in bulk.

  • Tag vocabulary sidebar with confirmed/suggested counts
  • Lasso fills the table; untagged-only filter
  • Checkbox bulk confirm / add tag
C

Flow builder

Click to place stages; a corridor around the route pulls in tracks. The bottom panel shows the set as a colour-coded timeline and a play-order list.

  • Insert, drag or delete stages; ⌘Z / ⇧⌘Z
  • Radius + target length
  • Play the flow straight through

Questions to answer while clicking around

  1. Which should be the home view? These could all be modes of one app (e.g. Map / Tag / Build tabs).
  2. Tagging: is it per-track in a panel (A), bulk in a table (B), or both?
  3. Flow builder: does stage placement feel right? Should radius be adjustable per stage?
  4. Playback: click plays, ⌥+hover auditions from 40% in. Right split?
  5. What do you colour by most: cluster, tagged-ness, BPM or a tag score?
  6. Are cluster labels on the map useful, or clutter?
